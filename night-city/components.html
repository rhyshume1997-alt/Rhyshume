Rive, for web design

A Rive file is a small animated, clickable graphic that you drop into a page the way you drop in an image. It moves, it reacts to the mouse, and your page can feed it numbers.

Think of the difference between a photo of a light switch and a real one. A PNG or a video is the photo. A Rive file is the switch: it has states (off, on, hovered), it knows how to move between them, and it does that live in the browser. One file with the extension .riv holds the artwork, the animation and the rules.

Your page can drive it

A Rive file can expose named values, such as speed. Your page sets the value and the graphic follows: the needle turns, the arc grows, the number changes. This is how a gauge, a progress bar, a price or a user's name gets into an animation.

// the three lines behind those sliders
const dash = gauge.viewModelInstance;
dash.number('speed').value = 240;
dash.boolean('boost').value = true;

Putting one on your own page

  1. Put two files next to your page. Your graphic, hero.riv, and the Rive player, which is a script plus a .wasm file from the free @rive-app/webgl2 package.

  2. Add a canvas where the graphic should appear.

    <canvas id="hero" width="640" height="360"></canvas>
<script src="vendor/rive.js"></script>

  3. Tell the player which file and which canvas.

    <script>
  rive.RuntimeLoader.setWasmUrl('vendor/rive.wasm');
  const hero = new rive.Rive({
    src: 'hero.riv',
    canvas: document.getElementById('hero'),
    stateMachine: 'State Machine 1',  // the rules inside the file
    autoplay: true,
    autoBind: true,                    // lets the page set its values
  });
</script>

That is the whole integration for a plain HTML site. In React the same thing is one component from @rive-app/react-webgl2. On iOS, Android and Flutter there is a matching player, and the same .riv file runs in all of them.

Where it earns its place

  • Hero graphicsAn illustration that moves and follows the cursor, at a fraction of a video's size.
  • Buttons and togglesHover, press and success states drawn once and reused everywhere.
  • Loaders and empty statesSomething pleasant to watch while a page works.
  • IconsA menu icon that becomes a close icon, a heart that fills.
  • MascotsA character that blinks, waves and reacts to what the visitor does.
  • Live numbersGauges, progress rings and charts driven by your data.

Making a new one

There are two ways in, and they produce the same file.

  • Ask for it. With the Rive CLI installed, describe what you want to Claude Code: an animated logo, a pricing toggle, a loader in your brand colours. It writes the scene as text files, checks it by rendering frames, and builds the .riv.
  • Draw it. Open the Rive Editor in a browser and design, rig and animate by hand. A file made by the CLI opens there too, so a designer can take over.

Building the finished file takes one command, rive <project> --publish, after signing in once with rive login. A free account works; free builds open with a short Rive splash.
