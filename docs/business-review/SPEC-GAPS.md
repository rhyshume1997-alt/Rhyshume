# Spec gaps, risks and decisions for Rhys

Each item: what the issue is, then the recommendation. "Search summary" means the fact came from search result summaries quoting an official page, because direct fetches of google.com, iso.org and ico.org.uk pages were blocked in this environment.

## Decisions needed before building starts

1. **Automation page price line.** The copy branch puts "Automation and AI set up is from £200" on `automation.html` (main had no price there). It is an approved existing line, but the new brief says no prices for new automation, SEO or AI visibility work. Recommendation: keep it worded as the small existing set up item on the websites and small business page only, and on the automation page use "Discuss your requirements" with no figure. WP-E follows your answer. 
2. **Competitor discovery provider (cost and terms).** Google Places Text Search is the only provider that gives names, websites and ratings reliably; it needs a Google Cloud billing account, roughly 3 to 7 pence per review after a small free allowance (search summary of Google's pricing page; unverified Enterprise tier for website fields), and its terms limit how long results may be kept (place ID storable, location 30 days, other content not retained beyond transient caching: search summary of the service specific terms, newest wording not confirmed). Recommendation: build the boundary now, ship it **disabled**, rely on "visitor names one competitor" at launch; decide on Places after reading the current Places policies yourself. If you enable it, reports and competitor data expire at 30 days (already the design).
3. **AI visibility provider and budget.** Four supported APIs exist (Anthropic web search, OpenAI Responses web search, Gemini Google Search grounding, Perplexity Sonar). All cost money; indicative $10 to $14 per 1,000 searches plus tokens, so about £0.30 to £3 for a full assessment (10 questions x 3 runs x 1 to 2 tools). Recommendation: pick one provider, set a daily cap in pence (default 0 = off), run assessments only from the admin view for leads you choose, and keep the public review at "awaiting a supported test". Consumer products (ChatGPT web, Google AI Mode) must not be automated: OpenAI's terms prohibit programmatic extraction apart from the API, and Google treats automated search queries as a policy violation (search summaries, third party in part). Read the chosen provider's current terms on evaluation and storing outputs; they were not retrieved.
4. **Privacy notice, lawful basis and ICO registration.** The notice does not cover Supabase, the Google Sheet, Anthropic (concept builder), Vercel logs, review reports, tokens or the new providers, and it says you are not registered with the ICO. I could not read the ICO fee guidance, so whether registration (or an exemption) applies is **not verified**. Recommendation: confirm the ICO position yourself first (ICO's self assessment), approve the retention periods (proposed: report links 30 days, anonymous review data 90 days, report email addresses cleared after 30 days, open prospects kept while open), approve three separate consents (deliver report, contact me about results, marketing which stays off and unused), then WP-E updates `privacy.html`. No marketing email will be sent by the system in any case. Competitor business names appear in reports about named third parties: the wording is restricted to measured facts with dates; you may want a short note on the bot page and the report ("data about other businesses comes from public sources").
5. **Supabase service role key and applying the migration.** Server side writes need `SUPABASE_SERVICE_ROLE_KEY` as a new Sensitive variable, and the migration must be applied to the live project. Neither is done. Recommendation: apply the migration first to a Supabase branch or a scratch project (steps in MIGRATION-NOTES.md), run the API tests against it, then to production when you approve. Treat the service key as the highest value secret in the project (it bypasses all RLS).
6. **ISO wording.** Search summaries of iso.org pages show ISO 9001:2026 (edition 6) published (ISO announcement 16 September 2026), ISO 9000:2026 (edition 5) published May 2026, ISO 13485:2016 (edition 3) current and confirmed in 2025. Your belief that both 2026 editions were published in November 2026 is not matched (May and September). Recommendation: on the site write the standard numbers without years ("ISO 9000, ISO 9001 and ISO 13485"), say "familiar with the quality management principles", never "compliant", "certified", "aligned" or "validated against"; do not quote standard text. Re-check iso.org on the day you publish before adding any year.

## Impossible or not meaningfully possible in the first release

7. **Google Business Profile, Maps ranking, review counts for the visitor's own business.** No verified public data source without a provider and consent (and Maps ranking has no supported source at all). The report marks this "not tested / no supported source". `verified_authenticated_account_data` is defined but cannot occur until you connect owner accounts (Search Console, Business Profile). Recommendation: leave it; offer it as a paid assessment step.
8. **Full AI visibility inside the free instant review.** Costs and runtimes (30 plus calls) do not fit a free anonymous tool. Recommendation as in 3.
9. **A PDF.** There is no PDF library or headless browser in the repo, and the hand written PDF writer you mention is not in this repository. First release: print view ("Save as PDF" from the browser). Optional later: a small dependency free text PDF writer. No pretend PDF button.
10. **Verified Maps style "local pack" competitors for service area businesses.** Places search ranks by its own relevance; "electricians serving Glasgow" will include some that are not direct competitors. The selection rules filter and show reasons, and you can reject or replace; some reviews will still end with one nominated competitor or none.

## Risks and costs

11. **PageSpeed Insights quota and terms.** Third party pages quote 25,000 queries a day and 400 per 100 seconds with a key, and a small shared pool without one; I could not read Google's quota page or terms. Recommendation: create a restricted key, cap at 150 calls a day in code, check the Cloud Console quota page before launch. Lighthouse scores are lab data and vary run to run; the report never calls them ranking scores.
12. **Function time and plan limits.** Your Vercel plan and function count limit could not be verified. The design uses 60 second steps and two new functions to be safe on any plan. If your plan allows long functions we can raise the step budget later. Cron frequency on a free plan is limited (not verified); the review does not depend on cron.
13. **Preview deployments are behind Vercel login (SSO) and have none of the new variables.** A pushed branch cannot be tried by the public, and the Preview environment lacks Resend, Turnstile and Supabase variables. Turnstile also only accepts `rhyshume.co.uk` hostnames in the existing code. Recommendation: test on a preview with you logged in and add Preview variables yourself, or use Cloudflare's documented test keys for the preview environment (not verified from the source here). No settings were changed.
14. **Rate limits are only as good as the database counters.** Done with Supabase atomic counters plus Turnstile plus daily caps; a determined attacker rotating addresses can exhaust the daily caps (visitors then see "daily limit reached", nobody is charged beyond the caps). A Vercel firewall rule would add a layer; it was not touched and plan availability is unverified.
15. **The existing safe fetch lacks DNS pinning.** `api/upgrade-live.js` can in theory be fooled by DNS rebinding. Not changed (out of scope). Recommendation: a separate later task to point it at the new `safe-fetch.js`.
16. **Single personal identity.** The workbook login, every database policy and the enquiry inbox are all the personal Gmail address, and that address is also in two visitor facing error messages (`api/contact.js` and `form-check.js`). WP-E changes the visible messages to `rhys@rhyshume.co.uk`. Changing the owner identity is a bigger task and is not planned.
17. **Hosted workbook file is public.** Only data is protected. The new admin screen is code only; no review data is ever in the file. Keep it that way.
18. **Crawling third party sites.** The tool fetches the visitor's site and up to three competitor sites with a declared user agent, robots.txt honoured, at most 25 requests per review. Some sites will block it; that shows as "not tested". The bot page explains this.
19. **No browser test tooling in the repo.** Browser checks (mobile, tablet, desktop, keyboard) need Playwright from outside the tree; WP-F lists them in the test plan and results will be reported as run outside the repo.
20. **Claims discipline.** Report wording never says a competitor is more successful or is taking customers, never gives revenue estimates, and labels commercial hypotheses as inferences. Tests ban the causal phrases. If you want stronger sales language, that is a decision for you, not a default.
21. **Existing copy tests.** Changing copy breaks assertions in `test/home.test.js`, `pages.test.js`, `flagship.test.js`; WP-E updates them in the same commit as the copy. The 254 baseline must stay green.
