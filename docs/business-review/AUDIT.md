## 4. Safe fetching today (relevant to SSRF requirement)

`upgrade-live.js` already has `ipIsPublic`, `assertHostIsPublic`, `makeFetch` (manual redirects, max 4, each hop re-checked, 10 s per request, overall deadline). It blocks the usual IPv4 and IPv6 ranges with `net.BlockList`, rejects credentials and ports other than 80 and 443, and handles `::ffff:a.b.c.d`. Gaps against the spec:

1. **No DNS pinning.** It resolves the name to check it, then `fetch` resolves it again. A DNS rebinding attacker can return a public address first and `127.0.0.1` or `169.254.169.254` second. 
2. `::ffff:7f00:1` (hex form of an IPv4 mapped address) is not matched by its regex, and NAT64 `64:ff9b::/96` is blocked only as a whole prefix. Needs a normalising step.
3. No response size cap and no content type check (it relies on the builder). No robots.txt handling (not needed there, needed for a crawler).
4. It is private to that file (`module.exports.assertHostIsPublic`). The new module should not import from an API handler.

Decision: write a new `api/_lib/br/safe-fetch.js` (pinned `lookup` on `https.request`, size and time caps). Do not edit `upgrade-live.js` (out of scope, hard rule); recommend a later separate task to move it onto the new module.

## 7. The hosted workbook (`w-82503121e7fdf54e/index.html`, 4815 lines, one file)

- Static page with a built-in Supabase client: `CLOUD = { url: https://vkpdrqkwxkokolphmkbh.supabase.co, key: sb_publishable_..., table: 'client_workbooks' }` (publishable key, public by design). State object `CL` (screens `login`, `list`, `work`).
- Auth: Supabase magic link. `clSend` posts to `/auth/v1/otp`; `clTakeHash` reads `access_token`/`refresh_token` from the URL hash; session in `localStorage` key `client-workbook-auth-v1`; `clToken()` refreshes via `/auth/v1/token?grant_type=refresh_token`; `jwtEmail` decodes the email. `cloudGate()` returns the login or client list HTML instead of the app until `CL.screen === 'work'`. The hosted copy has no offline button (the meeting build script strips it). The page itself is public static; only data is protected by RLS.
- Data access: `clRest(path, {table, method, body, rpc, prefer})` wraps PostgREST with `Authorization: Bearer <access token>`. `cloudSave` PATCHes `client_workbooks` (`client_name`, `data` jsonb = whole state `S`, `updated_at` optimistic concurrency via `updated_at=eq.`). So **a new key on `S` (for example `S.review`) is stored with no schema change**.
- Leads: `clLoadList` reads `leads?handled=eq.false&select=id,created_at,name,business,email,phone,message,picks&order=created_at.desc`, rendered as "New lead / Waiting for Rhys". `leadmk` ("Make into a client") builds a draft client from the lead (`S.client.business`, `contact`, `status='enquiry'`, `S.lead={email,phone,at}`, picks into the requirements, `enquiryPrefill(l)`), creates the `client_workbooks` row, then PATCHes the lead `handled=true, workbook_id`. **This is exactly the "convert to draft project" path the review should feed**, so review leads should be rows in `leads`.
- Public lead creation: `/request-a-quote` posts to the RPC `lead_submit` with the publishable key (consent required, validation, 30 per hour, 3 per hour per email).
- Client portal `c-09b37e50c043baaa`: RPCs `portal_open/save/quote/quote_accept` by hashed token; the same token pattern (`sha256` of a random token, `active` flag) is reused for review tokens.
- Module system: `tools/workbook-meeting/build.py <source html> <out html>` splices CSS and JS into the built workbook with exact string anchors (`rep(old, new)`, exits "anchor not found" on drift, refuses if a marker is already present), adds a nav item (`{ id: 'meeting', g: '1 Client', ...}`), a view (`meeting: vMeeting`), hooks in `shell()` and `init()`. The committed workbook file already contains the meeting module. A reviews module follows the same pattern and must run **after** it.

## 13. Summary of risks to design around

1. No server side database access exists today and no package manager: Supabase must be reached with `fetch` and a new service role variable.
2. Per instance rate limits are not real limits: use Supabase counters (DECISIONS 7).
3. Safe fetch lacks DNS pinning: new module.
4. Every paid provider is currently unconfigured, so the first release honestly shows "unavailable" for discovery, AI visibility and (without a key) a reduced PageSpeed quota.
5. Privacy notice and ICO registration statement need Rhys's review before new personal data is processed.
6. Nav and copy are duplicated across about 23 files: a single owner must change them.
7. Preview deployments require Vercel SSO login.
